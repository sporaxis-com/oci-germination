# Changelog

Release history for the two bundles this repo currently cuts under the
**CKP v3.9 Critical Isolation Alpha** track:

- `ociger-ck-allinone` — the consumer-facing all-in-one (`ghcr.io/sporaxis-com/ociger-ck-allinone`)
- `ociger-pg18-pgrdf-pgck-nats-micro` — the pg base it consumes (`ghcr.io/sporaxis-com/ociger-pg18-pgrdf-pgck-nats-micro`); pg17 retired at the pg18 move (og#9)

## Format

Every release **attempt** is recorded — both successful and failed.

- **SHIPPED** entries published to GHCR and verified attested. Each has a git tag and a digest.
- **FAILED** entries hit a CI gate before any artifact reached GHCR. They have no git tag; their context is captured here so the gap in the version sequence is explained.

Each entry carries three lines so the historical record reads cleanly:

- **Tried** — the intent of the cut (what was being changed and why).
- **Tested** — the CI gates that ran and their outcome. For pg_base that's: Go unit tests, generator round-trip, generated-files-committed assertion, pgRDF preload lint, multi-arch build, **10-check smoke** (pg ready, pgRDF + pgCK + pgcrypto installed, version-match check, NATS core PONG, NATS WSS port up), SLSA Build Provenance v1 attest. For ck-allinone the smoke is bundle-specific: pg ready, §A auto-bootstrap extensions, NATS core, NATS WSS, busybox httpd serves `/cklib/*`, root WSS round-trip landing, WSS round-trip from sidecar, **§B4 dispatch-bridge round-trip** (input.kernel.<K>.action.<verb> → ckp.dispatch → result.kernel.<K>.<verb>), Python-free check, PID 1 = s6-svscan.
- **Verdict** — SHIPPED with digest + attestation status, or FAILED with the specific step that failed and the cause.

See [PROVENANCE.md](./PROVENANCE.md) §Release attempt policy for the rules that govern this file and how it interacts with `LATEST.md`.

## Policy summary (full text in PROVENANCE.md)

1. **Version numbers are monotonic and never reused.** A failed CI attempt at `vN.M.K` permanently retires that number. The next attempt is `vN.M.(K+1)`, never a re-push of `vN.M.K`.
2. **CHANGELOG.md captures every attempt; git tags are created only for successful attempts.** Gaps in the version sequence are explained here.
3. **LATEST.md advances only when SLSA Build Provenance v1 verifies the GHCR digest** — the auto-regen workflow is the only sanctioned writer.

> **Note on transition:** the **2026-06-10 / 2026-06-11 waves below include two entries (`pg_base v0.1.8` and `pg_base v0.1.11`) where a failed first attempt was retried under the same tag** before this policy was set. Under the policy now in force those would have advanced to the next version number instead. The honest history is recorded as-is.

### v0.7.43 — the door ships CLOSED; identity posture declared in env, never derived ⚠ BREAKING
> **Entry written retrospectively on 2026-09-04.** v0.7.43 shipped and attested on 2026-09-03 with **no CHANGELOG entry**, which the policy above forbids — every release is supposed to be recorded here. Recorded now rather than left as a gap; the omission is the record.
- **BREAKING for realm-configured doors, and for a bare `docker run`.** The image bakes `ENV OCIGER_CK_ADMIT_ANONYMOUS=off`. Previously **nothing wrote `pgck.admit_anonymous` at all**, so it sat at pgCK's built-in `on` reading `source: default` — an **unowned** value. A realm door therefore verified tokens *and* admitted unverified ones, and a token failing verification (wrong audience, expired, foreign realm) was silently **downgraded** to `urn:ckp:participant:anon` rather than refused: the client saw an open socket and no error, and only the broker log told the difference.
- **The finding was never "on is wrong".** pgCK's anonymous tier is a documented capability (verified → publish, unverified → subscribe-only), and a deployment running a realm plus a public read-only tier uses it deliberately. What changed is which way the **shipped default** points, and that the value became **owned**: it now reads `source: configuration file` from `/run/ck-identity/pgck.conf`, which the provisioner regenerates at **every container start** — so unlike an operator's `ALTER SYSTEM` (which lands in PGDATA and dies with the next `down -v`) it cannot silently revert. `OCIGER_CK_ADMIT_ANONYMOUS=on` keeps the mixed tier.
- **The default lives in the ENV and nowhere else.** `resolveAdmitAnonymous()` reads the variable and derives nothing; an emptied declaration is refused rather than defaulted. An earlier revision of this change computed the value in Go from whether a realm resolved — visible in a log, but not in `docker inspect`, which is the same class of defect as `source: default`. `OCIGER_CK_POSTURE`, added mid-cut, was **removed before shipping**: with the tier declared by `ADMIT_ANONYMOUS` and the verifier by whether the JWKS resolves, it was a third way to say the same thing. Surface stays at 16 variables.
- **Three boot refusals**, named clause, non-zero exit, before postgres starts — shipped in the same commit as the default because closing the tier turns a previously harmless misconfiguration into a fatal one (verify everything, with no key to verify against): closed + no realm (the bare-`docker run` case, whose message leads with **deliver a JWKS** and gives the mount line); realm materials set but not resolving; the declaration emptied. All refusals carry the `REFUSED` marker so `grep REFUSED` finds every one. The boot log now prints one posture block carrying the **expected audience** and the **usable Ed25519 key count + kids** — both previously absent, and an audience mismatch used to cost several wire probes plus a JWKS decode to diagnose.
- **Tested:** `preflight-local.sh` green with the exit code consulted directly; `tests/local-tdd` gained cases 10 (the image ships baked=off, read from `Config.Env`, so a Dockerfile flip fails even though the harness overrides it; plus declared-env-reaches-substrate and sourcefile ≠ `postgresql.auto.conf`) and 11 (throwaway containers per refusal, **container state as the oracle rather than log text**, and a silent refusal fails too — on this default the message *is* the documentation). Three call sites now declare the tier they exercise rather than inheriting it.
