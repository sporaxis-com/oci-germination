ck-allinone — /wss/

NATS WebSocket endpoint. You only see this page if you hit /wss/ with a plain HTTP GET (not a WebSocket upgrade) and you don't have a gateway in front of the container.

This path is the routing contract, not the WebSocket itself. Inside the container, the NATS WSS listener is on :9222. Busybox httpd serves THIS static info page at /wss/ as a documentation surface; it does NOT proxy WebSocket upgrades.

Two valid topologies

Direct docker run — publish :9222 on the host and talk to it directly:

docker run -p 8000:8000 -p 9222:9222 ghcr.io/sporaxis-com/ociger-ck-allinone:latest
# Browser:  ws://<host>:9222
# CLI:      nats --server ws://<host>:9222 ...

Behind envoy / gateway (TLS-fronted) — route the public /wss path to ws://<container>:9222. Example envoy route:

routes:
- match: { prefix: /wss }
  route:
    cluster: ck-allinone-nats-wss
    upgrade_configs:
    - upgrade_type: websocket

Browser then opens wss://<host>/wss; the gateway upgrades and proxies to :9222 inside the container. The landing page at / auto-detects this topology from location.protocol.

Verifying the WSS endpoint

Direct mode:

curl -sI -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
     -H 'Sec-WebSocket-Version: 13' -H 'Sec-WebSocket-Key: x' \
     http://<host>:9222/  # 101 Switching Protocols

Gateway mode:

curl -sI -H 'Connection: Upgrade' -H 'Upgrade: websocket' \
     -H 'Sec-WebSocket-Version: 13' -H 'Sec-WebSocket-Key: x' \
     https://<host>/wss  # 101 Switching Protocols
